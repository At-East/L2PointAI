# 把 L2PointAI 导入 Visual Studio 2026

## 一、最可靠的方式：打开“解决方案”

```
L2PointAI.sln            ← 双击这个（不是 .csproj）
L2PointAI.csproj         ← SDK 格式工程，VS 2022/2026 直接支持
L2PointAI.Legacy.csproj  ← 旧式工程，仅 VS 2019 或更早需要
```

IDE 内：`文件 → 打开 → 项目/解决方案…` → 选 `L2PointAI.sln` → `Ctrl+Shift+B` 生成 → `F5` 运行。

命令行（最不容易受文件关联影响）：

```powershell
& "E:\VisualStudio2026\Common7\IDE\devenv.exe" "E:\文档\unilidar_l2\L2PointAI\L2PointAI.sln"
```

## 二、为什么双击 .csproj「没反应」

1. **文件关联走的是启动器，不是 IDE**
   `HKEY_CLASSES_ROOT\.csproj` → `VisualStudio.Launcher.csproj.15.0`
   → `"C:\Program Files (x86)\Common Files\Microsoft Shared\MSEnv\VSLauncher.exe" "%1"`
   启动器会挑一个“注册过的实例”。本机同时装了 **Community（E:\VisualStudio2026）** 和
   **Build Tools 2026（C:\Program Files (x86)\Microsoft Visual Studio\18\BuildTools）**，
   后者只有 MSBuild、没有界面 —— 落到它就等于什么都没弹出来。

2. **旧式工程（ToolsVersion 15.0）在 VS 2026 里已不是首选格式**
   现在工程已改为 SDK 格式（`<Project Sdk="Microsoft.NET.Sdk">` + `net48`），VS 2026 原生支持。

3. **IDE 启动失败时会“静默退出”**
   用日志可以看到真实原因，例如受限账户/策略下会出现：

   ```
   [Error] VisualStudio :: Failed to initialize Registry Root Hive
   [Error] VisualStudio :: Failure calling InitializeAppID.
   ```

   这种情况 IDE 会直接退出，看起来就是“点了没反应”。

## 三、逐步排查

1. 任务管理器里看 `devenv.exe` 是否**一闪而过**。
2. 带日志启动，然后看 `ActivityLog`：
   ```powershell
   & "E:\VisualStudio2026\Common7\IDE\devenv.exe" "E:\文档\unilidar_l2\L2PointAI\L2PointAI.sln" /log "%TEMP%\vs.log" /nosplash
   ```
   在 `%TEMP%\vs.log` 里搜 `Error`。
3. 确认打开的是 **IDE** 而不是 Build Tools：
   开始菜单搜 “Visual Studio 2026” → 打开后应出现起始页（Build Tools 没有起始页）。
4. 修默认打开方式：右键 `L2PointAI.sln` → 打开方式 → 选择 “Visual Studio 2026” → 勾选“始终使用”。
5. 若提示“项目类型不受支持”：说明装的是 Build Tools。用 VS Installer 安装工作负载
   **“.NET 桌面开发”**（含 .NET Framework 4.8 目标包）。

## 四、不依赖 IDE 的构建方式

```powershell
# 方式 A：dotnet CLI（本机已装 .NET SDK 11）
dotnet build L2PointAI.csproj -c Release

# 方式 B：系统自带 csc.exe（不需要 SDK）
powershell -ExecutionPolicy Bypass -File .\build.ps1

# 方式 C：VS 2026 的 MSBuild（验证过可用）
& "E:\VisualStudio2026\MSBuild\Current\Bin\MSBuild.exe" L2PointAI.sln /t:Restore;Build /p:Configuration=Release
```

> 注意：在受限沙箱/无桌面会话里，`dotnet build` 与 MSBuild 可能报
> `Access to the path '\\.\pipe\LOCAL\dotnet_xxx' is denied`（Roslyn 编译器服务器用命名管道）。
> 加 `-p:UseSharedCompilation=false` 即可绕过；正常桌面环境不会遇到。

## 五、工程配置说明

- 目标框架 **net48**：Win10 20H2+ / Win11 自带运行时，不额外装包
- `LangVersion 5`：同一份源码既能被 VS 编译，也能被系统 `csc.exe` 编译
- `ApplicationIcon` + `ApplicationManifest`：图标与 DPI 感知清单由 SDK 自动嵌入
- `GenerateAssemblyInfo=false`：版本信息统一由 `src/AssemblyInfo.cs` 提供
- 无 PackageReference：`NuGet.config` 清空包源，restore 离线秒完成

## 六、`Ctrl+Alt+L` 没反应怎么办

`Ctrl+Alt+L` 是“解决方案资源管理器”的经典默认快捷键，但在下面三种情况下会失效：

1. **当前不是解决方案上下文**（只打开了文件夹、单个文件，或工程加载失败）→ 该命令被禁用，按了也无声息
2. **快捷键被改绑**：VS 2026 允许切换键盘方案，或被你装过的插件改过
3. **被其它程序抢占**：输入法、录屏/显卡工具、远程桌面工具常占用 `Ctrl+Alt+*`

三步走：

| 办法 | 操作 |
|---|---|
| 用菜单（不依赖快捷键） | **视图 → 解决方案资源管理器** |
| 恢复被关掉/隐藏的面板 | **窗口 → 重置窗口布局** |
| 确认/修改快捷键 | **工具 → 选项 → 环境 → 键盘**，搜索 `View.SolutionExplorer`，看“所选命令的快捷键”是否为空，可重新分配 |

右侧竖排的“解决方案资源管理器”“团队资源管理器”字样是**自动隐藏**的工具窗：单击标签可弹出，点标签右侧的图钉可固定。

如果菜单里根本找不到“解决方案资源管理器”，说明当前窗口不是解决方案视图：
`文件 → 打开 → 项目/解决方案…` → 选 `L2PointAI.sln`；
或直接命令行打开某个文件：

```powershell
& "E:\VisualStudio2026\Common7\IDE\devenv.exe" /edit "E:\文档\unilidar_l2\L2PointAI\src\MainForm.cs"
```

## 七、完全不依赖 IDE 的一键脚本

```powershell
.\run.ps1                    # 编译 Debug 并启动
.\run.ps1 -Release           # 编译 Release 并启动
.\run.ps1 -NoBuild           # 直接启动已有 exe
.\run.ps1 -NoLaunch          # 只编译
```

脚本会自动用 vswhere 找到 VS 的 MSBuild，找不到再回退到常见路径与 .NET Framework 自带 MSBuild。
（在受限沙箱里 Roslyn 编译器服务器会因命名管道被拒，可加 `-NoSharedCompilation`。）
